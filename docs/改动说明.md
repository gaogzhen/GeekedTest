# 定制化说明

本仓库基于上游 [xKiian/GeekedTest](https://github.com/xKiian/GeekedTest) 做了针对性改造，聚焦 **Geetest v4 图标点选（icon）** 验证码。

> 上游原版说明请见 [readme.md](../readme.md)。

---

## 一、核心改动

| 项 | 上游 | 本仓库 |
|---|---|---|
| 图标检测 | ddddocr 通用检测 | **自训练 YOLOv8n 8 方向检测** |
| 方向分类 | ddddocr + `geetest_v4_icon.onnx` | **YOLO 一步输出方向** |
| 配置 | 分散在各文件 | **根 `config.py` 统一** |
| 日志 | 大量 `print` | **`utils/logger.py` 分级** |
| 训练流程 | 无 | **`training/scripts/` 全流程脚本化** |
| 水平翻转 | 默认 `fliplr=0.5` | **`fliplr=0.0`** |

## 二、当前通过率

| 版本 | 训练数据 | fliplr | 实测通过率 |
|---|---|---|---|
| v7（基线） | 500 张人工 | 0.5 | 40–65%（波动大） |
| v10 | 1000 张人工 | 0.5 | 40–50% |
| **v11b（推荐）** | **1000 张人工** | **0.0** | **95%** ✅ |

## 三、关键突破点：必须关闭水平翻转

### 问题

Ultralytics **默认 `fliplr=0.5`**，训练时 50% 概率水平翻转图片，但 **YOLO 标签不会跟着翻转**。

对**方向分类任务**，这是致命的：

| 原图 | 标签 | 翻转后 | 标签（未变） | 模型学到 |
|---|---|---|---|---|
| 鱼头朝左 | `l` | 鱼头朝右 | `l`（错） | 朝右也是 `l` |

**结果**：模型分不清 `l` 和 `r`、`lu` 和 `ru`、`ld` 和 `rd`。

### 现象

| 现象 | 解释 |
|---|---|
| `u`、`d` 一直最准 | 水平翻转不改变上下方向 |
| `l` ↔ `r`、`lu` ↔ `ru` 反复混淆 | 水平翻转导致 |
| 验证集 mAP 高，实测差 | 验证集也用了同样的翻转，指标看起来正常 |
| 同一版本不同次训练通过率波动大 | 翻转是随机的 |

### 解决

训练时**显式关闭**：

```bash
fliplr=0.0
flipud=0.0
